# PRISM Photos — Person Photo Profile & Find More Photos

## Scope
This phase turns a single-person Photos view into a compact person photo profile and adds a person-centric, human-confirmed discovery workflow: "I know this person; show me other photographs that may contain them."

## Behaviour
- Exactly one selected person is presented as a profile; the redundant single-person chip/filter UI is suppressed.
- Two or more selected people remain a multi-person Photos search workspace.
- `Select` moves into the media toolbar for People-filtered galleries.
- Admin/HoD identity reviewers get `Find more photos` on a single-person profile.
- Possible appearances are read from the existing current-model candidate evidence generated by the background matcher.
- Candidate suggestions require a current trusted matching reference and canonical media visibility.
- At most one suggested face is surfaced per photograph (the strongest valid candidate), reducing detector-overlap duplication.
- Nothing is preselected and PRISM never confirms a person automatically.
- Reviewers can explicitly choose `Yes, <person>` or `Not <person>`, individually or in batches.
- Confirmation/rejection is revalidated server-side against current pending candidate evidence and current trusted references immediately before mutation.
- Confirmation uses the existing human-confirmed assignment/audit pipeline; rejection is face/person-specific and preserves other candidate identities.
- Batch confirmation retains the existing same-photograph and current-embedding integrity checks.
- Confirm/reject actions use AJAX when available and gracefully fall back to POST/redirect.
- Lightweight status polling runs only while background matching is active and never reloads the page.
- Normal authorised Photos users can view confirmed person photos but cannot see machine-generated identity suggestions; the workflow uses the existing Admin/HoD reviewer boundary.

## Persistence
No EF migration is required. The phase reuses existing MediaFaceReviewDecision, trusted-reference, assignment, candidate-state and identity-audit data.

## Compatibility
The package is a delta over the current consolidated baseline (Albums + matching-recovery + subsequent options/query/DI compatibility hotfixes). It deliberately preserves those registrations/options and adds only the person-profile services and UI.
