# Code review — September 2026

Scope: the whole repository at `master` @ `2e26b42` (deployed build). Method: a full Release build, the .NET and JS
test suites, a real PostgreSQL 16 migration run, a check of GitHub Actions history, and module-by-module code reading
done alongside the documentation refresh. Findings marked **✔ reproduced** were confirmed by running code or by
direct inspection during the review. The others are from code reading, with the file/line evidence given.

Severity: **High** = data loss, outage or security exposure in the deployed configuration; **Medium** = incorrect
behaviour or latent failure under realistic conditions; **Low** = hygiene, consistency or defence in depth.

## High

| # | Area | Finding | Evidence | Suggested fix |
| --- | --- | --- | --- | --- |
| H1 | Migrations | **A fresh database cannot be migrated.** ✔ reproduced | `Migrations/20260301090000_AddDocRepoExternalLinks.Designer.cs` (and `20260718123000_…`, `20260801090000_…`) build their target model by subclassing the live `ApplicationDbContextModelSnapshot`. The snapshot declares `ActionSprint` → `b.Navigation("Tasks")` before the `ActionTaskItem` → `WithMany("Tasks")` relationship, so EF throws "Navigation … Tasks was not found". `dotnet ef database update` on an empty PostgreSQL 16 database stops after 10 of 115 migrations. With that block moved to after the relationship, all 115 apply. Production survives only because it is already past these migrations; a new environment, a test server, or a rebuild-from-migrations DR path fails at startup. | Move the `ActionSprint` navigation block after the relationship block in the snapshot. Longer term, give the three migrations frozen Designer models instead of the live snapshot. |
| H2 | Security | **Committed user files are published and served anonymously.** ✔ | 111 files are tracked under `wwwroot/uploads/` (activity photos and PDFs, IPR attachments, visit photos, project photo derivatives). `wwwroot` is published, and `app.UseStaticFiles` (`Program.cs`) runs before authentication, so `/uploads/...` is reachable without login on the production server, even though production stores new uploads under `F:/ProjectManagementData/uploads`. Another 209 runtime files are tracked under `App_Data/` (DocRepo PDFs, FFC files, media cache). | `git rm --cached` both trees, add them to `.gitignore`, delete the published copies on the server, and check whether any of those files are sensitive. |
| H3 | Availability | **Login rate limiter is global.** ✔ | `Program.cs` `AddRateLimiter`: `AddFixedWindowLimiter("login")` (10 permits / 5 min, no partition key) is applied to the whole `LoginModel` class, GET included (`Areas/Identity/Pages/Account/Login.cshtml.cs`). Ten login page loads across **all** users in a 5-minute window return 503 to everyone, so one client can lock everyone out. `docUpload` has the same problem (10 per minute site-wide). | Use `RateLimitPartition.GetFixedWindowLimiter` keyed by client IP (and/or user name), and apply it to POST only. |
| H4 | Availability | **Background workers can stop the web host.** ✔ | .NET 8 defaults `BackgroundServiceExceptionBehavior` to `StopHost`, and the repo never overrides it. `Services/UserPurgeWorker.cs` catches only `TaskCanceledException`, and `Services/SearchV2/Indexing/SearchIndexWorker.cs` catches only `OperationCanceledException`, so a transient database error in either stops the whole site. `TodoPurgeWorker` and `LoginAggregationWorker` catch outside their loops and stop silently after one failure. | Wrap each loop iteration in `try/catch (Exception)` with logging and back-off; consider `HostOptions.BackgroundServiceExceptionBehavior = Ignore` as a backstop. |
| H5 | Data integrity | **Purging a project that appears in a briefing deck always fails.** ✔ | `ApplicationDbContext`: `ProjectBriefingDeckItem.Project` is `OnDelete(Restrict)` (also in migration `20261202090000_AddProjectBriefingDecks`). `ProjectModerationService.PurgeProjectDatabaseRecordsAsync` removes photos, videos, documents, comments, remarks, ToT, stages and plan snapshots, but not deck items. The purge rolls back, and `ProjectRetentionWorker` retries and fails every day. | Delete deck items in the purge, or change the FK to Cascade. |
| H6 | Operations | **The Windows publish script can never succeed.** | `ops/publish/create-publish-folder.ps1` expects exactly 62 migration IDs ending `20261201160000_…`; the manifest has 115 ending `20261216230000_AllowDuplicateActivityTitles`. | Derive the expected list from `Migrations/immutable-migration-ids.txt`. |
| H7 | Operations | **The PowerShell DB backup/restore scripts break at startup.** | `ops/backup-db.ps1` and `ops/restore-db.ps1` declare `param([string]$Host …)`, which collides with PowerShell's read-only automatic `$Host` variable ("Cannot overwrite variable Host"). Not run here because PowerShell isn't available in the review environment. | Rename to `$DbHost`, then test a real backup and a restore. |

## Low

- **Forwarded headers are trusted from any source** (`KnownNetworks`/`KnownProxies` cleared), so `X-Forwarded-For` can be spoofed into audit IPs.
- **`/Developer` is anonymous** and shows a personal email and phone number to unauthenticated visitors.
- **Password-change enforcement applies to Razor Pages only**: `EnforcePasswordChangeFilter` is a page filter, so users flagged `MustChangePassword` can still call the APIs.
- **`DP_KEYS_DIR` falls back to `/var/pm/keys`**, which on Windows resolves to the drive root, outside the backed-up data root.
- **Other purge and delete gaps:**
  - `POST /api/projects/{id}/purge` skips the retention wait and the name confirmation that the Admin Trash page enforces.
  - The DocRepo purge deletes the file before `SaveChanges`.
  - The Industry Partner attachment is saved to disk before the DB commit and trusts the declared MIME type.
- **Trashed or archived projects stay reachable** from Overview and the approvals queue.
- **`timestamptz` defaults of `now() at time zone 'utc'`** are skewed unless the database server's time zone is UTC.
- **Navigation doesn't match page policies:**
  - Social media links need `ManageSocialMediaEvents`, while the pages are plain `[Authorize]`.
  - HoD has no link to Holidays or to the social-media type/platform pages.
  - "My Workspace" is shown to roles that are then redirected.
  - The FFC report is gated by the ARPP view policy, so ITO cannot open it.
- **Dead code and config:**
  - `AllowAnonymousToPage("/Privacy")` refers to a page that doesn't exist.
  - `MediaLibrarySchemaInitializerWorker` is never registered.
  - `Database:ApplyMigrationsOnStartup` is ignored, yet the admin health page reports it.
  - `DocRepo:EnableAutoApplyFilters` and `MediaLibrary:AutoMigrate` are never read.
  - `SmtpEmailSender` disposes its client while a send is in flight, but nothing sends email.
  - `EnableVirusScan=true` would make every upload throw because no `IVirusScanner` is registered.
- **Remarks and plans:**
  - The ToT page context remark picks the External type for Project Office users, which `RemarkService` rejects, so the remark is dropped.
  - `RemarkApi.MapServiceException` matches outdated message text, so External and Conference denials return 400 instead of 403.
  - `PlanApprovalService` checks "already pending" then acts, with no unique index behind it, so two pending plans can be created.
  - The Procurement supply-order "future date" check uses the UTC date, so today's date is rejected between 00:00 and 05:30 IST.
- **`tools/check-views.sh`**: the inline-script and event-handler checks never match (a look-ahead `rg` rejects, and a double-escaped `\\b`).
- **Repository hygiene**: about 300 historical delivery artefacts in the root (see the root README).

## What was checked and found sound

- Every page except `/`, Login, AccessDenied, Error and Developer carries `[Authorize]` or a policy. `IgnoreAntiforgeryToken` appears only on Error, and no GET handler makes meaningful state changes.
- Notebook API: every query is scoped to the owner or a collaborator, and Viewer/Editor/Owner levels are enforced.
- Search V2 SQL is fully parameterised, and authorization is applied in SQL before ranking. Legacy hits are filtered by access.
- File path handling (`FileSystemPathResolver.EnsureWithinRoot`, media cache roots, server-generated DocRepo keys) resists traversal, and symlinks are skipped.
- The Release build compiles cleanly (8 nullable warnings).
