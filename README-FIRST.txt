PRISM ERP — Project Ideas Governance & Discussion Lifecycle
Ready-to-paste package — 09 Aug 2026

PURPOSE
This phase completes the governance/lifecycle gaps identified in Project Ideas without redesigning the module.

IMPLEMENTED
1. Discussion default by role
   - Comdt: Conference is selected by default.
   - Every other role: General is selected by default.
   - Multi-role users containing Comdt follow the Comdt default.
   - The server owns the default; the Razor UI and client initialise from that value.

2. Discussion remark edit/delete parity with Project Remarks
   - General: author may edit/delete within 3 hours; Comdt/HoD/Admin override.
   - Conference: Comdt/HoD only, matching the existing Project Remarks conference rule.
   - Conference edits retain original author, issue time, role snapshot and Status when issued.
   - Delete is soft-delete; deleted Conference directions stop participating in operational Conference Review calculations.
   - Inline edit, compact action menu, Edited state and PRISM confirmation are included.

3. Controlled Idea deletion
   - Comdt/HoD/Admin may delete any Idea.
   - Other roles cannot delete Ideas.
   - Delete requires a reason and is soft-delete only.
   - Discussion, notes, documents and files remain stored.
   - Deleted Ideas are removed from ordinary operational Idea queries.
   - A privileged Deleted Ideas recovery page allows restoration.

4. Concurrency and audit hardening
   - ProjectIdea and ProjectIdeaComment now use application-generated byte[] concurrency tokens.
   - Edit, archive, restore, Idea delete/restore and discussion mutation paths use friendly optimistic-concurrency handling.
   - New Idea/comment create/edit/delete and Idea delete/restore actions use the central PRISM audit service where supplied.

5. Database migration
   - 20261207210000_AddProjectIdeaGovernanceLifecycle
   - Adds lifecycle/edit metadata and RowVersion fields.
   - Backfills RowVersion for existing rows before enforcing NOT NULL.

INSTALLATION
Copy the contents of this folder over the ProjectManagement project root, preserving paths and replacing the listed files.

Then run the normal project validation/deployment flow, for example:

    dotnet restore .\ProjectManagement.sln
    dotnet build .\ProjectManagement.sln -c Release --no-restore
    dotnet test .\ProjectManagement.Tests\ProjectManagement.Tests.csproj -c Release --no-build

If JavaScript dependencies are not already restored:

    npm ci
    npm test

Apply the included EF Core migration through the application's normal migration/deployment mechanism.

IMPORTANT
- No permanent deletion of Idea documents/files is performed by this feature.
- No current Notebook front-end files are replaced.
- OfficerConferenceReadService.cs is intentionally NOT included; current Conference/Notebook variants should remain untouched. Existing workload queries already exclude soft-deleted Ideas and direction queries already exclude soft-deleted Conference comments.

See TEST-RESULTS.txt for validation completed in the packaging environment.
